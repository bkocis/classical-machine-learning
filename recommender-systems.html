Chapter 1: Learning to Rank (LTR) - Detailed Explanation

🧠 What Is Learning to Rank?

Learning to Rank (LTR) is a type of machine learning technique used to automatically construct ranking models — typically for:

  • Search engines (ranking documents for a query)
  • Recommendation systems
  • Online advertising (ranking ads by relevance)
  • E-commerce (ranking products by likelihood of purchase)

Instead of manually designing ranking heuristics like TF-IDF, LTR learns how to order items using training data that reflects user preferences or relevance.

🎯 The Core Idea

The goal is to learn a scoring function f(x) that assigns a numerical relevance score to each item given a query, so that higher scores correspond to higher relevance.

Then, for each query, we sort items by their predicted scores to produce the ranking.

📊 The Three Main Approaches

1. Pointwise

  • Treats each document independently.
  • Model predicts an absolute relevance score (regression or classification).
  • Examples: Logistic Regression, Linear Regression.
  • Pros: Simple and intuitive.
  • Cons: Ignores relationships between documents.

2. Pairwise

  • Learns to compare two items and decide which should rank higher.
  • Examples: RankNet, SVMRank.
  • Pros: Optimizes relative order.
  • Cons: Computationally expensive (O(n²) comparisons).

3. Listwise

  • Considers the entire list at once.
  • Examples: LambdaMART, ListNet.
  • Pros: Directly optimizes ranking metrics.
  • Cons: Computationally complex.

⚙️ Typical Pipeline

  1. Feature Extraction — Build query-document features (TF-IDF, click data, etc.)
  2. Labeling — Use user interactions or human judgments
  3. Model Training — Algorithms like XGBoost, LambdaMART, RankNet
  4. Evaluation — Metrics: NDCG, MAP, Precision@k
  5. Deployment — Rank new items at runtime

🧩 Example: LambdaMART

LambdaMART combines LambdaRank (pairwise gradients) with MART (Gradient Boosted Decision Trees). It learns gradients (“lambdas”) that improve NDCG directly and is widely used in search and recommendation systems.

🧠 Neural Learning-to-Rank

  • Cross-encoders: jointly encode query + document
  • Bi-encoders: encode them separately and compare embeddings

These capture semantic meaning and user intent better than traditional features.

📈 Example Use Case: Hotel Search

Query: “family-friendly hotels in Berlin”

Features: text match, rating, price, distance, amenities

Model Output: ranks hotels by predicted relevance or conversion likelihood

📚 Summary

Pointwise: simple but ignores context

Pairwise: optimizes relative order

Listwise: directly optimizes ranking metric

Chapter 2: Matrix Factorization for Collaborative Filtering

🧩 The Basic Idea

Matrix factorization is one of the most widely used techniques in collaborative filtering — especially in recommendation systems. It helps uncover latent factors that explain observed user–item interactions.

Given a user–item matrix R, the model assumes:

Rui ≈ puT qi

where:

  • pu is a latent feature vector for user u
  • qi is a latent feature vector for item i

The goal is to learn these vectors so their dot product approximates the known ratings.

⚙️ The Optimization Objective

We minimize reconstruction error for known ratings:

minP,Q Σ (Rui - puT qi)² + λ (||pu||² + ||qi||²)

  • K = set of observed user–item pairs
  • λ = regularization term

Optimization is typically done with Stochastic Gradient Descent (SGD) or Alternating Least Squares (ALS).

🧠 Intuition Behind Latent Factors

Matrix factorization uncovers hidden features describing both users and items.

  • For movies: latent factors might represent genre preference or complexity.
  • A user vector captures preferences across these dimensions.
  • An item vector captures how strongly it exhibits each factor.
  • The dot product predicts how much the user will like the item.

📈 Variants and Extensions

  • SVD (Singular Value Decomposition) – works well for dense matrices.
  • FunkSVD – practical model optimized via SGD (used in Netflix Prize).
  • Biased MF Model – adds bias terms for user/item tendencies: Rui = μ + bu + bi + puT qi
  • Implicit Feedback MF – handles binary or confidence-weighted data (clicks, views).

🧮 Example (Python)

import numpy as np

num_users, num_items = R.shape
k = 10
P = np.random.rand(num_users, k)
Q = np.random.rand(num_items, k)

for u, i, r_ui in known_ratings:
    err = r_ui - np.dot(P[u], Q[i])
    P[u] += lr * (err * Q[i] - lambda_ * P[u])
    Q[i] += lr * (err * P[u] - lambda_ * Q[i])

🚀 Advantages

  • Scales to large datasets
  • Captures low-dimensional patterns
  • Easily extendable (biases, hybrid models, etc.)

⚠️ Limitations

  • Struggles with cold start (new users/items)
  • Requires tuning for regularization and dimension size
  • May miss nonlinear interactions (deep learning handles these better)

Chapter 3: Ranking Evaluation Metrics Explained

1. Precision@k

Purpose: Measures how many of the top-k retrieved items are relevant.

Formula: Precision@k = (# of relevant items in top k) / k

Example: If the top-5 retrieved documents contain 3 relevant ones → Precision@5 = 0.6

Interpretation:

  • Higher is better
  • Easy to interpret
  • Doesn’t consider order among top-k items

2. MAP (Mean Average Precision)

Purpose: Evaluates ranking across multiple queries, considering precision at each relevant position.

Formulas:

  • Average Precision (AP) = (1/R) × Σ [P@k × rel(k)]
  • Mean Average Precision (MAP) = (1/Q) × Σ [AP(q)]

Example: AP = [0.8, 0.6, 1.0] → MAP = 0.8

Interpretation:

  • Considers ranking order
  • Rewards early relevance
  • Common in retrieval benchmarks

3. NDCG (Normalized Discounted Cumulative Gain)

Purpose: Measures ranking quality when items have graded relevance.

Formulas:

  • DCG@k = Σ [(2^reli - 1) / log2(i + 1)]
  • NDCG@k = DCG@k / IDCG@k

Example: DCG@5 = 7.0, IDCG@5 = 10.0 → NDCG@5 = 0.7

Interpretation:

  • Captures position sensitivity and graded relevance
  • Widely used in search and recommendation systems

Chapter 4: Understanding XGBoost and LightGBM

🌳 Gradient Boosting — The Core Idea

Goal: Combine many weak learners (usually shallow trees) into a strong model.

How it works:

  1. Start with a simple model (like mean prediction).
  2. Compute residuals (errors).
  3. Fit a new tree to predict residuals.
  4. Add new tree predictions to the existing model (scaled by learning rate).
  5. Repeat many times — each tree fixes prior mistakes.

Essentially, this is gradient descent over decision trees.

⚙️ XGBoost (Extreme Gradient Boosting)

Developed by Tianqi Chen (2014), XGBoost is a highly optimized and regularized version of gradient boosting.

Key Features

  • Regularization (L1, L2)
  • Second-order optimization
  • Tree pruning (max_depth, gamma)
  • Handles missing data
  • Parallel and distributed computing

Use Cases

  • Kaggle competitions
  • Credit scoring
  • Forecasting
  • Feature importance analysis

⚡ LightGBM (Light Gradient Boosting Machine)

Developed by Microsoft Research (2017), LightGBM focuses on speed and scalability.

Innovations

  • Leaf-wise tree growth
  • Histogram-based algorithm
  • Gradient-based One-Side Sampling (GOSS)
  • Exclusive Feature Bundling (EFB)
  • Distributed training

Typical Parameters

  • num_leaves, max_depth, learning_rate
  • feature_fraction, bagging_fraction
  • boosting_type = “gbdt”, “dart”, or “goss”

🧩 Comparison Summary

XGBoost

  • Level-wise tree growth
  • Slower but stable
  • Lower overfitting risk

LightGBM

  • Leaf-wise tree growth
  • Faster on large data
  • Slightly higher overfitting risk

🧠 When to Use Which

  • XGBoost: for stability, interpretability, and smaller datasets
  • LightGBM: for speed and massive datasets
